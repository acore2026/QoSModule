01 / Runtime architecture

软件运行架构

当前代码支持两种部署边界。独立Target是设计文档的直接实现；free6gc内嵌方式复用原UDP report入口，通过一个三行分流点接入同一套共享策略和RAN适配器。

切换部署方式查看组件边界和请求路径。

DEPLOYMENT A · STANDALONE TARGET 设计主路径 / 独立进程 / UDP入站 + HTTP出站
独立部署边界

Target拥有UDP监听和HTTP客户端，不修改UPF会话或QER。

共享业务核心

MASQUE协议适配、策略计算和RAN适配均来自独立adaptive-qos模块。

结果返回

RAN原始结果由Target写回本次UDP来源地址，再由MASQUE Proxy转给UE。

DEPLOYMENT B · FREE6GC IN-PROCESS ADAPTER 兼容部署 / 原文件三行分流 / 原AdaptiveReport链不变
最小上游改动

adaptive_qos.go只调用handleProjectQoSDatagram，不引入项目协议依赖。

双分支共存

项目请求走RAN API；非项目AdaptiveReport继续原Session和QER Override流程。

同一共享核心

Target与free6gc适配器使用相同Intent、BurstPolicy、Limits和ranapi。

02 / Code architecture

代码模块与依赖方向

两个运行入口只负责传输和项目边缘适配，核心模型、策略编排和RAN适配由独立Go module复用。 箭头表示编译期依赖或直接调用，核心模块不反向依赖Target和free6gc。

关键调用时序

独立Target和free6gc外挂的中间入口不同，但从协议校验到RAN结果回送的业务顺序一致。

08 / Gaps and assumptions

与设计不完全一致的地方

这些问题不会改变设计示例结果，但应在进入正式实现前明确或收敛。

A1

协议候选识别偏宽

当前出现任一marker就进入候选识别。建议要求完整主字段或增加message_type和protocol_version。

A2

时延默认值是实现假设

代码确定了0.8和100ms；文档只要求可配置比例或默认值，free6gc分支暂不可独立配置。

A3

舍入规则未写入设计

MBR/GBR除法向上取整，PDB和比例推导四舍五入。建议将规则写入协议或策略文档。

R1

HTTP会阻塞UDP读取循环

Target和free6gc reportLoop都同步等待RAN。逻辑一致，但高并发时应增加有界工作队列。
