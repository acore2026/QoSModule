Project orientation / start here

随路QoS项目与代码导览

这个项目接收MASQUE Proxy转发的QoS协同请求，根据必选UL Burst、可选DL Burst和时延预算计算 可用方向的MBR、GBR、PDB与优先级，按RAN接口范围裁剪并下发，再将RAN结果沿原UDP路径返回。 同一套业务核心既可以运行在独立Target中，也可以通过最小适配接入free6gc UPF。

2 可选运行入口
1 共享策略模块
4 核心QoS输出
+3 free6gc原文件改动行
输入 rnti、qfi、UL Burst、e2e_delay、可选DL Burst
策略 直接计算，不查询现有UPF QoS
输出 RAN API字段与成功/失败结果
兼容 原free6gc AdaptiveReport流程保持不变

05 / Domain model

数据如何逐层转换

外部JSON不会直接进入策略。masqueapi先把协议字段转换为稳定Intent； 策略输出Decision；ranapi再把Decision翻译为RAN接口字段。

masqueapi.Request JSON / 指针字段 / 协议命名
→
Intent Flow + UL Burst + optional DL Burst + Delay
→
Decision Target + Applied QoSValues
→
ranapi.Request q_mbr / q_gbr / q_pdb / q_pri
→
ApplyResult Status + RawResponse

Policy

Generate(ctx, Intent, Limits) (Decision, error)

决定“怎么算”。当前实现是BurstPolicy，其他项目可以替换自己的策略。

LimitsProvider

Limits(ctx, FlowSelector) (Limits, error)

决定“按什么范围裁剪”。当前使用StaticLimits，未来可接配置中心或UPF查询。

Enforcer

Apply(ctx, Intent, Decision) (ApplyResult, error)

决定“下发到哪里”。当前ranapi.Client调用RAN HTTP接口。

06 / Policy calculation

QoS策略怎样计算

UL必算，DL在请求携带完整DL Burst时独立计算。先得到目标值，再按RAN允许范围裁剪；当前不与现有UPF QoS合并。

MBR

MBR_kbps = Burst_Size_kB × 8 × 1000 ÷ Burst_Duration_ms
  • UL必算；DL字段完整时才计算DL
  • 整数除法向上取整
  • 按对应方向MBR范围裁剪

GBR

GBR_kbps = Burst_Size_kB × 8 × 1000 ÷ Transit_Delay_ms
  • 显式真实时延优先
  • 否则E2E × 0.8
  • DL缺失时不计算DL GBR

PDB / Priority

PDB_ms = round(E2E × 0.625) Priority = 3
  • E2E缺失或为0时拒绝
  • PDB裁剪到10–300ms
  • Priority裁剪到1–15

Strict input rule

UL必填，DL成对可选

  • ul_burst_size缺失或为0
  • ul_burst_duration缺失或为0
  • service_info.e2e_delay缺失或为0
  • dl_burst_size和dl_burst_duration同时缺失时允许，只更新UL
  • DL字段只带一个或值为0时拒绝
UL Burst1024 kB / 100ms
DL Burst2048 kB / 100ms
MBR UL / DL81920 / 163840
GBR Target DL128000 kbps
GBR Applied DL100000 kbps
PDB / Priority100ms / 3

基站侧开发与联调需要确认什么

10 / Decisions and open design

已经确定和仍需明确的边界

已确定项直接约束当前代码；待明确项目前采用可配置或保守默认实现。

DECIDED

不查询现有QoS

当前直接使用Burst和时延计算结果，UPF查询不参与策略，也不做PFCP modify。

DECIDED

RNTI和QFI必选

必须由MASQUE请求直接携带；source_address和UE IP只作为辅助信息。

DECIDED

UL Burst必选，DL Burst成对可选

UL size/duration和e2e_delay缺失或为0直接返回INVALID_PARAM；DL两个字段同时缺失时只更新UL。

DECIDED

计算后按RAN范围裁剪

MBR、GBR、PDB和Priority都先形成目标值，再形成最终下发值。

OPEN

真实传输时延协议字段

代码兼容多个候选字段，正式字段名称、来源和可信度仍需协议确定。

OPEN

舍入和单位

当前速率向上取整、PDB四舍五入；kB采用公式中的十进制倍率，需写入正式协议。

OPEN

RAN mask按字段顺序生成

默认只为实际出现在RAN JSON中的字段置bit；若RAN正式bit定义不同，需要调整映射表。

OPEN

并发和幂等

当前同步等待RAN HTTP；请求重试、request_id幂等和有界并发尚未定义。
